## Purpose

This document is the **single, canonical pull-list** for deferred items across IntentTree —
features, enhancements, and known gaps that were explicitly deferred during a prior effort.

- **During planning**: scan this list for items related to (or higher-priority than) the
  feature you are about to scope. Pull them into the plan when they fit the same surface.
- **During debugging / execution**: whenever you *decide to defer* something, add a `DI-` row
  here before ending the turn (check first that it isn't already captured).

The capture/check protocol and the (modular) location pointer live in
[`.claude/rules/deferred-backlog.md`](../../.claude/rules/deferred-backlog.md). That rule file
is the one place to edit if the backlog ever moves into IntentTree itself (captured as nodes via
the `intenttree-cli` skill) or is fed from `meatycapture`.

  next free number — do not renumber existing rows (other docs cite these IDs).
- **Origin** cites the source effort + that effort's local ID (e.g. `v3.1 H1`, `parity UI-003`) so
  the detailed write-up stays traceable. Keep the detailed origin docs in place; this table is the index.
- **When an item resolves**: flip Status to `resolved`, append the closing commit/effort, and leave the
  row (traceability over deletion).
- **Cross-references** between related items use the `DI-` IDs inline (e.g. "Relates to DI-015").
