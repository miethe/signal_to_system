## The headline — the device check belongs at the START of a round, not the end

Simulator-side structural tests certified Reader scrolling **twice** — at M3 and again at M4 — and
hardware failed it **both times**. The M4 device pass (flag-ON build of `92dd832`, throwaway worktree,
flip never committed) terminated early on a blocking defect: *"the text jumps around as scrolling, it
jumps back to the top frequently or gets hung"* (D10 verbatim,
`.claude/worknotes/primary-pattern-reader/user-directives.md` §D10). The remaining checklist items
(counters, sheets, a11y) were **not executed** — not recorded, not assumed.

Two costs, and the second is the expensive one. First, a milestone's worth of enrichment work was
built on top of an interaction that does not hold on device. Second, the *product* answer changed at
the device pass — D10 supersedes the D5/D6 joystick-scrub model the rail was designed around — so
this was never a bug that a fix leg could close; it was a design premise that hardware falsified.

**Change, now encoded in the v2 spec**: rail-scroll-v2 mandates a **device session at round START**,
before implementation, not as the final gate. A structural test can prove a scroll *contract*; it
cannot prove scrolling *feels right*, and on this surface the felt behaviour **is** the requirement.
Evidence: `m4-gate-plan-and-routing.md` §"On-device check — 2026-08-02 — FAILED".

## What worked

### 1. The same-class stop rule fired correctly at G1 round 2

G1 (security lens, R6 redaction, codex `gpt-5.6-terra`) ran two rounds. Round 1 returned 3 findings,
all accepted, all real — defect class *redaction-boundary enforcement gaps* (`reader_session_id` not
UUID-validated; the allowlist bypassable via public `TelemetryService.record`; a DEBUG
`ImportCorpusExporter` time-window path sweeping `reader_*` events into a shareable bundle). Round 2
(re-pass 1 of the 2-re-pass budget) over `f75e111` found the synthesized `Codable init(from:)`
bypassing the scrub — **the same defect class one hop further out**.

The stop rule says: same class twice → close with a **design change**, not a third adversarial round.
So `TASK-M4.G1-fix2` made the scrubbing designated initializer the *only* materialization funnel
(custom `init(from:)` delegating into it), verified in-session by
`TelemetryEventDecodeScrubTests` (7/7 green), and G1 closed. One documented residual: valid-UUID bytes
as a covert channel — **REJECTED as threat-model overreach**, accepted as a residual, and the contract
prose softened in both tiers so they cannot disagree about what is being claimed
(`ReaderTelemetryPayloadContract.ValueKind.identifier` / `ReaderTelemetryValueKind.identifier`).

Worth naming: the rule saved a review round *and* produced the better artifact. A third round would
have found a fourth bypass; the funnel closes the class.

### 2. Every ICA leg delivered — the M3 AAR's preamble fix held

All implementation legs were routed to ICA and **all of them returned real work this run**, against
M3's pattern of silent no-ops. The M3 AAR's remedy — open every ICA prompt with *"YOU ARE THE
EXECUTOR; your final message is the deliverable"* — was applied to every leg
(`m4-gate-plan-and-routing.md` §"Leg reliability preflight") and the failure mode did not recur. The
companion discipline still ran: `git status --porcelain` checked on disk after every leg, a leg's own
report never trusted.

### 3. Legs reported the deviations they could not resolve, instead of inventing scope

B1 hit G16's *Segmented*-tier enrichment row and found it unreachable: §9.5 detail lines gate on
`.enrichedStepExpansion`, which M1 grants only for `tier >= .structuredPattern` **and**
`signals.hasEnrichedStep` — and `HeuristicPatternStructurer` output satisfies neither. Lighting it up
would have meant changing the **M1 capability matrix**, against the task's own instruction ("bind to
the M1 capability model — do not invent a parallel one"). The leg shipped what was honest at that tier
(the Stitch Info entry point, deliberately not expansion-gated) and escalated the rest as an operator
decision. Same posture on C2: six real a11y gaps fixed at their own surfaces, five more **filed, not
fixed**, each with the reason it was out of scope (cross-feature surface, or new behaviour rather than
an a11y adaptation).

## What went wrong

### 1. The full-suite green claim was pinned to the wrong commit

The recorded pre-flip evidence — **3,192 tests green** — was taken *before* the two G1 fix commits
(`f75e111`, `92dd832`). After those landed, only a **targeted** run happened (the decode-scrub suite
plus adjacent telemetry suites, 14 + 62 tests, and `-only-testing:LNDomainTests` at 725). So for a
stretch of this run the artifact of record said "full suite green" while the tree under review was two
commits ahead of that log. The close-out session re-ran the full suite **at HEAD** before the
validator gate (`/Users/miethe/.claude/jobs/5b20d934/tmp/full-suite-at-head.log`); notable in that
re-run, `LNDomainTests` came back **725/725 with zero failures** — the two `StructuringTextWindowTests`
B-19 environment flakes carried through the whole milestone did **not** reproduce.

**Lesson**: a "full suite green" claim is not a property of a milestone, it is a property of a
**commit**. State the SHA it ran at, or it decays silently the moment the next fix lands. A targeted
re-run after a fix proves the fix; it does not re-prove the suite.

### 2. The G1 fix leg recompressed two unrelated binary evidence files

`f75e111` carries `Bin 37749 -> 37825 bytes` and `Bin 37699 -> 37807 bytes` on
`p5-t2-action-entitled.png` / `p5-t2-upsell-unentitled.png` — **premium-server-offload** evidence
assets with nothing to do with the telemetry redaction boundary. Reverted in the wrap-up commit
(`87a3645`). No content was lost, but a security-fix diff carrying byte churn in another feature's
evidence is exactly the noise that makes a reviewer's job harder, and it survived a codex re-pass
because the lens reads the source change, not the asset bytes.

**Change**: add a checklist line at fix-leg dispatch — *no binary files in a fix diff*; if
`--stat` shows `Bin`, revert those paths before commit.

### 3. `op context pack` returned a node-side path on this Mac

At M4 dispatch, `op context pack` emitted `/home/miethe/...` (a **[REDACTED]** path) that does not
exist locally, so the per-leg delegation-context bundle was skipped for the whole milestone; legs got
path-pointer prompts instead (M3 precedent). Non-blocking here, but it is a **launchpad bug** —
`op context pack` appears to resolve its run dir against the remote host when the op run store is
node-backed. Logged at `implementation-notes.md` §"2026-08-01 — M4 orchestration notes"; worth a fix
upstream rather than a third milestone of workaround.

### 4. A grep exit code read as a test failure

`grep -c` over a test log returned **0 matches and therefore exit status 1**, which read as a failed
check and briefly presented a **green** suite as a failing one. Cost was minutes, not a decision, but
it is the mirror image of the standing rule (*read the `** TEST SUCCEEDED **` verdict line, never grep
✘ counts*): a counting grep's exit code carries no information about the suite, only about whether the
pattern matched.
