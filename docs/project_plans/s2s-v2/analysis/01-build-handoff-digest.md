## 1. Mission and IA in 10 lines

Mission: "the public face of Nick Miethe's multidisciplinary research and engineering practice: questions investigated, evidence exposed, ideas developed in public, and systems people can inspect and reuse" (`START-HERE.md:7`, `specs/00-mission-and-experience.md:9-13` via MASTER-SPEC.md:72-74). Explicitly **not** a bigger blog, a research-dashboard, or a public mirror of private agents (`START-HERE.md:9`). AI is a subject and a method, never the organizing gate — math, cognition, philosophy, design, acoustics, woodworking, photography stand on their own (MASTER-SPEC.md:74). Primary nav is fixed: **Writing · Labs · Projects · Notebooks · Studio** (`START-HERE.md:13`, MASTER-SPEC.md:93). Writing subsumes Essays, Field Notes, Dev Stories, Guides, Companions as format labels on one feed, not five silos (MASTER-SPEC.md:95, 191). Notebooks stay intentionally unresolved thought, distinct from finished writing (MASTER-SPEC.md:95, 369). Projects is the single canonical catalog; Portfolio is a curated professional-audience view over it, never a second data store (MASTER-SPEC.md:95, 421-425). Studio absorbs the existing `@miethe/ui`/component showcase plus three design languages — Observatory, Folio, Instrument — sharing one semantic token system (MASTER-SPEC.md:510-514). The experience contract is Understand → Inspect → Reuse → Contribute (MASTER-SPEC.md:80-83), realized as a non-linear graph `question ↔ notebook ↔ investigation ↔ evidence ↔ writing ↔ project ↔ artifact ↔ external response` (MASTER-SPEC.md:87). Secondary nav (Start Here, Programs, Domains, About, Portfolio, Other Sites, Search, Feeds, Agent Guide, Methods, Corrections, Colophon) exists but must never visually compete with the five primaries (MASTER-SPEC.md:97).

## 4. ADRs and key contracts/schemas

Eight ADRs, all status "accepted handoff direction; reconcile against stronger repository/owner constraints" and all pointing verification back to spec 14 rather than asserting their own proof (`adrs/*.md`):

- **001 writing-hub** (`adrs/001-writing-hub.md:9-11`): Writing is a *view* over existing `posts`/`stories`, not a new store — rejects both "Essays only" and "merge everything into Notebooks."
- **002 static-public-projection** (`adrs/002-static-public-projection.md:9-15`): approved snapshots are the durable public input; RF/SkillMeat stay separately-qualified services the site never reads live from the browser.
- **003 preserve-canonicals** (`adrs/003-preserve-canonicals.md:9-15`): per-record/path/fragment manifest + deliberate redirects only — explicitly rejects "move all old URLs in one rewrite." Taxonomy ≠ URL (a Field Note can keep an `/essays/...` path).
- **004 component-reuse** (`adrs/004-component-reuse.md:9-15`): inspect `@miethe/ui` and existing Figure/Evidence/Story components first; starter adapters are prototypes to be *replaced* during integration while their acceptance tests survive.
- **005 explicit-agent-contract** (`adrs/005-explicit-agent-contract.md:9-15`): HTML/Markdown/JSON parity with exact refs and explicit install/execute=false; no hidden prompts; remote MCP is a later, separately-qualified thing.
- **006 corrections-versus-withdrawal** (`adrs/006-corrections-versus-withdrawal.md:9-15`): corrections version-and-annotate; rights withdrawal blocks/purges/prevents rollback resurrection — two different mechanisms, never merged.
- **007 selective-dependencies** (`adrs/007-selective-dependencies.md:9-15`): static/native → existing package → focused library only after a compatibility/performance/rights spike. Rejects "install everything recommended."
- **008 one-analytics-owner** (`adrs/008-one-analytics-owner.md:9-15`): audit real account wiring before wiring anything; exactly one collector per stream.

**Contracts** (`contracts/`): `adapters.ts` (`contracts/adapters.ts:1-22`) defines the site-adapter interface every service integration must implement — `PublicRef{authority,type,id,version}`, `Lifecycle{state,checkedAt,invalidationGeneration,displayAllowed,reuseAllowed}`, `ExactResult<T>` (available | unavailable, never leaking hidden IDs), and `PublicReadAdapter<T>` with `catalog/getRecord/getLifecycle/getDependencies/getReleaseManifest`. Explicitly labeled "PROPOSED... inspect actual service contracts before writing adapters." `public-read.openapi.yaml` (`contracts/public-read.openapi.yaml:1-57`) sketches `/data/v1/catalog.json` and `/data/v1/publications/{id}/{version}.json` — bounded to 100 items/page, 404 must not distinguish nonexistent-vs-private, 410 only for approved tombstones.

**Schemas** (`schemas/`, JSON Schema 2020-12, `schemas/README.md:1-9`): nine boundary DTOs — `publication-record`, `claim-card`, `notebook-leaf`, `artifact-card`, `relationship`, `contribution-submission`, `film-card`, `approval-receipt`, `tombstone`. Deliberately narrow: "not Research Foundry/SkillMeat authority schemas," reject unknown fields at modeled boundaries. `claim-card` and `tombstone` are kept as separate shapes on purpose — a withdrawn record must not retain statement/source text once tombstoned. `publication-record` still permits `isFixture=true` for design testing, but the README states the *production* gate must reject that flag — meaning the schema alone under-constrains production safety and the gate logic (S2S-003/S2S-004) is doing the real enforcement, not the schema.

## 5. The starter reference core: what it actually is

`starter/README.md:1-24` and `starter/astro-integration/README.md:1-31` are unambiguous: **this is a behavioral reference, not shippable code.** The zero-dependency Node core lives at `starter/src/lib/public-lab/` — 8 `.mjs` modules: `safety.mjs` (escaping/HTML-script-safe JSON/link policy — explicitly "not a server SSRF validator"), `content.mjs`, `publication.mjs` (exact-byte approval gate, "protected approval source still required"), `relations.mjs`, `exports.mjs`, `analytics.mjs` (no network calls, no identifier store, no preconsent queue), `render.mjs` (the 12 safe render patterns), `client.mjs` (progressive enhancement). On top sit 13 files under `starter/src/components/public-lab/*.astro` — 12 pattern adapters (`ClaimCard`, `FigureWithData`, `NotebookLeaf`, `SourceEditionCard`, `ProceduralFilm`, `ReproductionCard`, `ArtifactCard`, `ProjectDestinations`, `QualificationStrip`, `CorrectionNotice`, `ContextCapsule`, `DomainMethodFacets`) plus one enhancement loader (`PublicLabEnhancements.astro`).

**Reusability verdict, in the handoff's own words:** "The Astro adapters were **not compiled** here" (`START-HERE.md:54`); "Astro wrappers and the example collection config were **not compiled here**, because Astro and its package dependencies are not installed and the container cannot reach the registry" (`starter/astro-integration/README.md:5`). The renderers use safe string generation "to permit a no-install reference harness... Port its tested behavior into existing native Astro components... this is not a new templating framework" (`starter/README.md:20`). So: the *behavior* (escaping rules, eligibility gates, typed exports) is validated and portable; the *Astro wiring* is unverified and is explicitly not to be adopted wholesale — ADR 004 says the same. Six workbench routes (`/`,`/writing/`,`/lab/`,`/notebook/`,`/projects/`,`/studio/`) are fixture routes, "not the proposed production route map" (`starter/README.md:18`).

**Validation state** (`validation/REPORT.md:1-40`): 73/73 Node contract tests, 27/27 JSON Schema cases, 51/51 offline Chromium DOM checks (1440/390/320px, no real browser navigation — blocked by `ERR_BLOCKED_BY_ADMINISTRATOR`), 22/22 package-structure checks. **Not executed at all:** actual Astro compilation/build/`astro check`, any live HTTP navigation, cross-browser/assistive-tech testing, any live RF/SkillMeat/GA4/Firebase/MCP connection, any research qualification. The validation report itself names this gap 6 separate times — it is the single most-repeated caveat in the entire handoff.

## 6. Reskin vs. rebuild: the handoff's stance, and route-preservation constraints

The clearest single line: **"Do not use that permission to restart the entire design or discard the existing polished essay experience"** — `specs/00-mission-and-experience.md:47` (also MASTER-SPEC.md:112). The permission being qualified there is "the overall homepage/header may be redesigned to support the new information architecture" (same line). Read together: this is a **targeted reskin of navigation/IA around a preserved core**, not a rebuild — Labs/Notebooks visual direction and the essay experience are baselines to extend, not replace.

Route-preservation constraints, gathered:
- No blanket `/essays/*` → `/writing/*` redirect, ever (`specs/02-information-architecture-and-migration.md`, MASTER-SPEC.md:223, repeated at MASTER-SPEC.md:15, 22).
- `/essays/:slug/`, `/essays/:slug/evidence/`, `/essays/:slug/figure/:id/`, `/essays/:slug/thread/:beat/` all preserved exactly, including anchor/fragment behavior (MASTER-SPEC.md:200-206).
- `/portfolio/ui/*` stays canonical for `@miethe/ui` docs in the first release; Studio only links to it — a future `/studio/components/*` migration requires a per-path redirect manifest (MASTER-SPEC.md:210, 451).
- `/dev-stories/`, `/series/`, `/aos/:area/`, `/systems/:project/`, `/other-sites/`, `/glossary/`, `/evidence/:record/`, `/rss.xml`, `/search.json` are all named do-not-break surfaces (MASTER-SPEC.md:205-220).
- `/workflow-showcase/` stays intentionally unlisted — "no promotion without review; private material must not be built at all" (MASTER-SPEC.md:218).
- A redirect is only emitted "after collision/chain/loop tests and content equivalence review" (MASTER-SPEC.md:241) — redirects are the exception path, not the default migration mechanism.
- `trailingSlash: 'ignore'` and `vite.ssr.noExternal: ['@miethe/ui']` in `astro.config.mjs` must not be touched as "incidental cleanup" (MASTER-SPEC.md:152, citing R05).

## 8. Risks, contradictions, gaps, and over-engineering signals

**Risks the handoff itself flags prominently:**
- Draft-leak risk in the *actual repo*: `getStaticPaths` on the essay route allegedly calls `getCollection('posts')` "without draft filter... later passes draft to layout" (R06, MASTER-SPEC.md:158) — flagged as "source risk, not verified live disclosure." This is unverified against the current checkout and should be the first thing an integrator actually checks, not assumed true.
- JSON-LD "ordinary stringify inside `set:html`" in `BaseLayout` (R10, MASTER-SPEC.md:163) — same caveat.
- Two competing project data sources (`projects` collection vs `portfolioItems` array) already diverged (R07/R08, MASTER-SPEC.md:160, 170) — non-trivial reconciliation work (S2S-012) sits on the Wave-1 critical path for Portfolio.
- Nine of 58 tasks are hard-gated on operator action (§3 above) — real bottleneck risk if Nick isn't available at the right moments, since several Wave-2/4/6 chains fan out from a single approval task (S2S-018, S2S-040/042).

**Contradictions / tensions worth naming:**
- The handoff repeatedly insists "a specification is not evidence of implementation" (every ADR's Verification line) while simultaneously shipping 30 component *contracts*, 9 schemas, and a fully-passing test suite that could easily be mistaken for a finished subsystem by a less careful reader — the validation report's six-times-repeated "not executed" caveat is doing real work to prevent that misreading, which itself signals the authors anticipated the confusion.
- Spec 02 says "the overall homepage/header may be redesigned" (MASTER-SPEC.md:112) but spec 00's audience-jobs framing and the design-continuity section keep pulling back toward "preserve... do not restart" — the boundary between "redesign the shell" and "restart the entire design" is asserted, not operationally defined (no diff-size threshold, no reviewer checklist beyond "screenshots and rationale" at MASTER-SPEC.md:520).
- `publication-record.schema.json` permits `isFixture=true` for testing while the prose insists production must reject it (`schemas/README.md:5`) — the schema is intentionally looser than the policy it supports; anyone validating "against schema" alone would pass unsafe fixture data.

**Gaps:**
- No installed-dependency reality check anywhere — Astro 6/React 19/Tailwind 4/`@miethe/ui ^0.2.0` are "declared ranges, not resolved lockfile" (R02, MASTER-SPEC.md:148) for the *whole* handoff; every downstream size/complexity estimate inherits this uncertainty.
- No accessibility testing beyond automated DOM checks at three breakpoints — screen-reader/keyboard/zoom work is 100% deferred to the receiving team (validation REPORT "Not executed" list).
- The "vertical slice" candidate selection (Registry Wave republish, or a Metis-film investigation) is left open (MASTER-SPEC.md:900-902) — Wave 2's entire critical path (§3) has no concrete content target yet, which means S2S-018 isn't just an approval gate, it's an *undefined* one.
- Analytics economics: Firebase Storage's Blaze-plan requirement (W11) and GA4/Firebase dual-collector risk (ADR 008) are named as traps but no budget number or alert threshold is proposed — "configure budgets/alerts" (MASTER-SPEC.md:708) without a figure is a placeholder, not a decision.

**Over-engineered for a one-person site — candidates:**
- Six orthogonal lifecycle axes (publication/evidence-evaluation/review/reproduction/software-maturity/destination-availability, MASTER-SPEC.md:541) plus 14 typed relationship edges (MASTER-SPEC.md:547) is publication-grade research-infrastructure modeling for a practice with, per the portfolio inventory, 16 projects and (as of this handoff) zero populated Lab investigations. The rigor is defensible for *evidence integrity*, but the schema surface (9 DTOs, 30 component contracts, an OpenAPI stub, an adapter interface) for a single flagship investigation (Wave 2's actual deliverable count: one) is a lot of scaffolding per unit of real content.
- Optional remote read-only MCP, contribution-intake state machines, and MediaWiki integration are all correctly deferred by the handoff's own stop-rules (spec 17, MASTER-SPEC.md:981-983) — the packet is self-aware about this risk even while including full specs for all three. Worth reading spec 17's "Stop rules" section literally as permission to *not* build Waves 4-5's service integrations until real demand shows up, rather than as a backlog to eventually clear.
- 13 candidate third-party libraries with individual qualification tasks (spec 16) for a site whose own ADR 007 title is "earn heavy libraries per interaction" — the qualification-task overhead (license/version/peer-dep/SSR/bundle-cost spike per library) is itself a mini-project per library; several (React Flow, Excalidraw editor mode, Media Chrome) may never earn their keep at this content volume and are correctly marked optional, but the amount of *process* defined for adopting them exceeds what a solo maintainer will likely execute faithfully wave after wave.
