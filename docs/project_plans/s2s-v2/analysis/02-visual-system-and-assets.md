# Visual System & Assets — S2S v2 Redesign

Source of truth for this analysis: `signal-to-system-visual-handoff-v2/` (mockups, transparent asset sheets, hero backgrounds, reference boards) compared against `signal-to-system-build-handoff-v2/design/` (the *approved* HTML prototype, its design-token JSON, and `approved-design-board.jpg`). Per project instruction, the visual-handoff mockups are the default source of truth for *look and feel*; the build-handoff prototype and its token files are the source of truth for *what is actually implementable and named* (the Observatory/Folio/Instrument system, the `--bg-*`/`--text-*` mapping contract). All ten site mockups are 1448×1086px; all four transparent asset sheets are 1448×1086px; both hero backgrounds are 1672×941px. Pixel regions below are estimates against those canvases, quoted as `x,y,w,h` from the top-left.

**One critical, load-bearing finding up front:** the visual-handoff mockups and the build-handoff prototype are not two views of the same design — they are two different color systems wearing the same three names. The mockups render "Observatory" as a saturated cosmic-purple night scene (glowing violet/lavender accents, near-black `#0a0d10`-ish canvas, neon icon glows). The build-handoff's `observatory.tokens.json` defines Observatory as a *much* quieter charcoal (`canvas #111517`, `accent #B8A5F2` — a soft, desaturated lavender, not neon). Same story for Folio (mockups imply cream notebook paper with sepia ink; tokens confirm cream `#F6F1E7`/`#FFFAF1` with a muted rust `#974B32` accent — close alignment) and Instrument (mockups show a light "clinical" panel; tokens confirm near-white `#F0F4F7`/`#FFFFFF` with a saturated blue `#244FB0` — also close). **Observatory is the one language where the mockups' saturation should be turned down toward the token file, not the reverse** — see §2.

## 2. The emerging design system

**Three named languages, one semantic system** (per the spec's own framing in `05-prior-handoffs/signal-to-system-full-build-specification.md` §07): status/meaning must not depend on which language is active. Concrete tokens below are taken verbatim from `design/initial-language-skill/*.tokens.json` (DTCG-2025.10-shaped, sRGB) and cross-checked against the mockups.

- **Observatory** (dark editorial default). Tokens: canvas `#111517`, surface `#191E21`, ink `#F3F0E9`, muted `#A9B4B7`, accent `#B8A5F2` (soft lavender), secondary `#9CCEB9` (sage green), rule `#3A4448`. **Mockups render this far more saturated** — the ten site mockups use something closer to `#0B0A12` canvas with a vivid violet `#8B5CF6`-`#A78BFA` glow and neon-outlined icons (see the icon grid, §4). **Recommendation: split the difference but land closer to the token file.** Keep Observatory dark and keep the violet identity (it's genuinely distinctive and matches the wordmark), but desaturate it 15–20% from what the mockups show — the mockups were generated as standalone "hero art," not as a full page of body text, and at reading-length that saturation will fatigue. The existing site's own `--bg-base:#0b1326` / `--accent:#6366f1` (indigo, from `src/styles/global.css`) is a reasonable third data point — it already sits between the two extremes and gives real precedent for "dark navy-black canvas, violet-indigo accent" as this site's established default. Converge Observatory's accent toward something in the `#7C6FE0`–`#9B87F5` range: warmer/lighter than existing `#6366f1`, cooler/darker than the mockups' brightest highlights.
- **Folio** (paper/ink editorial for Notebooks). Tokens: canvas `#F6F1E7`, surface `#FFFAF1`, ink `#302C29`, muted `#6E645B`, accent `#974B32` (terracotta/rust), secondary `#456759` (forest green), rule `#C9BDAD`. This one is well-aligned between token file, prototype screenshot (`05-notebook-folio.png`), and mockup (`signal_to_system_notebooks.png`) — all three agree on warm cream paper with rust-ink hand-drawn accents. **No correction needed; ship close to as-is.**
- **Instrument** (light technical for Studio/Methods). Tokens: canvas `#F0F4F7`, surface `#FFFFFF`, ink `#142D42`, muted `#4F6579`, accent `#244FB0` (saturated blue), secondary `#006D70` (teal), rule `#B9C7D2`. Also well-aligned across all three sources — this is the cleanest of the three languages and needs the least reconciliation.
- **Type pairing.** A serif display face (the wordmark and every mockup H1 — an old-style serif with high contrast, visible in "Signal to System," "A more rigorous relationship with reality.", and the Folio hand/ink italics) paired with a clean grotesque sans for UI/body (nav, buttons, labels, stat numbers) and a monospace for meta/status microtext (version strings, "S2S-DEMO-001", timestamps, chip labels like "DESIGN STUDY CONCEPT"). This is a three-way split, not the site's current two-family Inter/Noto-Serif/Space-Grotesk trio collapsed to one accent — keep three distinct roles. The token files don't name specific font families (no font files shipped, by design — see `SKILL.md`'s explicit note), so family selection is still open; the mockups' serif reads like a Georgia/Playfair-adjacent transitional serif, not Noto Serif's more static forms — worth an actual type audit against Google Fonts before locking.
- **Spacing/density.** Token space scale is a clean 4/8/12/16/24/32/48/64px ramp; reading width 720px, rail width 280px — both files agree on this exactly (identical values in all three token JSONs), so this is a hard cross-language contract, not a per-language variable. Mockup density is high (lots of stat tiles, multi-row card grids) but each card interior still respects generous internal padding — nothing touches edge-to-edge.
- **Iconography.** Two distinct icon languages appear and should NOT be merged: (1) the flat, thin-stroke UI icon grid (`neon_research_icon_grid.png`) — genuinely reusable, geometric, works at 20–24px; (2) the illustrated "sticker" artifacts (`cosmic_research_ui_sticker_sheet.png`) — rendered, painterly, decorative-only, never meant to sit inline at icon size. Motion hints are minimal in the static mockups but the Studio mockup's live language-switcher and the Lab detail's interactive figure ("Download data / View full figure") imply state transitions (tab switches, hover-reveal captions, exploratory chart interactions) rather than any ambient/ornamental motion — no parallax or particle animation is implied anywhere, which is good: keep motion functional.
- **Dark/light story.** Observatory and Instrument are the dark/light functional poles (editorial-default vs. technical-light); Folio is a third, warm-neutral option scoped specifically to Notebooks rather than a generic "light mode." This is a three-language system, not a binary dark/light toggle with a bonus skin — the Studio mockup's switcher UI (§1.7) should be the literal reference for how the toggle control looks and behaves site-wide, replacing the current single sun/moon icon toggle seen in every hero header.

## 3. Brand — logo, wordmark, favicon

**The field has two pools, not one.** `signal_to_system_logo_exploration_board.png` shows six unbuilt concepts (waveform-diamond lockup, dome-on-mountain lockup, constellation-triangle lockup, compass-rose lockup, an "S/S" slash monogram, plus a favicon-ideas strip trying four of these at 120px). Separately, the header actually used in all four *approved* prototype screenshots (`approved-design-board.jpg`) carries a seventh mark neither exploration file names: a simple ring crossed by a diagonal line that overshoots the ring on both ends — a signal-trail cutting through/escaping an orbit. Pixel-sampling that header (approved-design-board.jpg, region ≈95,210,225,50) confirms its two strokes already key to the token system: the ring samples ≈`rgb(130,121,174)` (the Observatory `accent` lavender `#B8A5F2`, darkened by JPEG/AA blending) and the trail samples ≈`rgb(99,137,126)` (the Observatory `secondary` sage `#9CCEB9`). No exploration-board candidate does this — none of the six is color-mapped to the token pair, and all six are drawn as single-hue gradients.

**Recommendation: ship the orbit/trail mark as primary.** It is the only candidate validated at real UI scale (it already reads cleanly at ~24–28px across all four theme screenshots, dark and light), it is trivial to hand-author (two strokes, no gradients, no raster), and its two-color structure means a theme switch is a CSS-variable swap, not a new asset — Folio becomes rust ring / forest trail, Instrument becomes blue ring / teal trail, using the exact secondary/accent pairs already in §2. Every exploration-board alternative fails at least one of these bars: the primary waveform-diamond lockup and favicon-01 waveform icon are multi-bar gradients that alias below ~32px; the observatory-dome favicon is a painterly illustration, not a flat mark, and ties the *universal* logo to one theme name (Observatory) when Folio/Instrument need to wear it too; the compass-rose lockup is thematically generic (navigation, not signal→system); the S/S slash monogram is an ornate interlocked serif that risks illegibility at 16px favicon size.

**Secondary/alt pick: the constellation-triangle lockup** (exploration board, region ≈560,455,400,220 — three connected nodes + a divider bar + wordmark). Drop its sparkle ticks and it reduces reasonably well; keep it in reserve as a "network" variant for contexts wanting a denser node-link motif (Studio's component library, a Labs section mark) rather than as the primary UI mark. Do not promote the diamond-waveform, dome, compass, or S/S monogram beyond decorative/merch use.

**SVG mark — geometry for the author.** ViewBox `0 0 32 32`, two independently-colorable strokes, no fill:
- **Ring:** a circle, center ≈(13,19), radius ≈8, stroke-width ≈2, stroke = `var(--accent)`.
- **Trail:** one straight line (a gentle painted arc is an acceptable refinement, a straight chord is what's approved today) from ≈(3,27) to ≈(27,5) — roughly a 24° incline off horizontal — passing through the ring's interior as a chord and overshooting the ring's boundary by ~30% of the radius at *both* ends, so the line visibly exits past the circle rather than stopping tangent to it. Stroke-width ≈1.5 (thinner than the ring), round caps, stroke = `var(--secondary)`.
- Keep ~2px of clear space inside the artboard so the mark doesn't crowd the wordmark or the browser-tab chrome at 16px.

**Wordmark lockup.** Horizontal: mark (~28–32px tall) + `Signal to System` in the serif display face, with `NICK MIETHE / INDEPENDENT INQUIRY` (or the site's existing `BY NICK MIETHE`) in tracked-caps monospace beneath — the exact proportions already validated in the approved-board header. Stacked variant (mark above wordmark, tighter kerning) for square contexts: app icon, social avatar.

**Favicon set.**
- `favicon.svg` — the mark above, its two `var(--accent)`/`var(--secondary)` refs resolved via a `<style>` block with a `@media (prefers-color-scheme: dark)` rule swapping between a light-canvas pair and the Observatory dark-canvas pair (lavender ring/sage trail). Chrome/Firefox/Edge re-render this live on OS theme change.
- PNG fallback, rendered from the same SVG (never upscaled from a small rasterization): **16×16**, **32×32** (tab/bookmark), **180×180** (apple-touch-icon, flattened onto a solid dark canvas — no transparency support there), **192×192**, **512×512** (PWA manifest), plus one **maskable 512×512** with the mark inset to the standard ~80% safe-zone circle and a solid (not transparent) background fill for Android adaptive icons.

**OG-image template.** 1200×630, Observatory-dark canvas regardless of the source page's active theme (one consistent dark background reads correctly across both light- and dark-mode host UIs — never ship a light-Folio OG card). Layout: mark + wordmark lockup top-left at ~64px; a tracked-caps page-type kicker reusing the format-pill vocabulary from §4 (`ESSAY` / `LAB` / `DEV STORY` / `PROJECT`); the page H1 set large in the serif display face, ≤3 lines, left-aligned mid-canvas; an optional one-line dek below at reduced opacity; a thin rule + `nickmiethe.com` bottom-left; for Lab pages only, a status pill (`Published`/`Active`/`In Progress`, same pill component as §4) bottom-right. No painterly hero art on the card itself — the illustrated hero backgrounds (§4) stay on-site; OG generation needs to be fast, legible at thumbnail size, and theme-independent.

## 6. Gaps

No mockup exists for any of the following — each needs its own design pass before build, not an inferred extension of a desktop mockup:

- **Mobile layouts, full stop.** All ten mockups (and both hero backgrounds) are fixed 1448×1086 desktop canvases; nothing shows how the header nav collapses, how the multi-column card grids stack, how the right rails relocate, or how the Studio tab bar / Dev Stories tab-row behave under ~768px.
- **Article/essay reading page.** No mockup renders a single long-form post in any language — the closest analog is the prototype's plain-sans fixture (§1.1), which is explicitly a placeholder, not a designed reading page. This is the single highest-traffic template with zero visual direction.
- **404 / not-found.** `src/pages/404.astro` exists in code; no mockup covers it.
- **Empty, loading, and error states.** No mockup shows an empty search result, an empty filtered card grid ("no Labs match these filters"), a failed data-fetch state, or a "report unavailable" state for a withdrawn/retracted investigation — notable given how much of the Labs/Notebooks IA is filter-driven.
- **Withdrawn / retracted / under-review states.** The taxonomy implies a lab or claim can move backward (Peer Reviewed → under correction), per the `CorrectionNotice` component named in the Studio library (§1.7) — but no mockup shows what that state looks like on a live investigation page.
- **Search results page.** `search.json.ts` exists as a data endpoint; no mockup shows the results UI the "Search" nav icon (§4) presumably opens into.
- **Series / reading-path detail page.** `series/[...slug].astro` and the Writing hub's "Reading paths" rail both imply a page that walks a multi-post sequence; no mockup shows it.
- **Tags / topics index and detail.** `tags/[tag].astro`, `tags/index.astro`, `topics/[topic].astro` exist as routes; no mockup covers the tag-cloud index or a single tag's filtered results.
- **Newsletter subscribe confirmation / error.** The Writing-hub newsletter strip (§1.4) shows the input + button only, no success/already-subscribed/invalid-email states.
- **Full detail page behind a `Private Summary` project.** The Projects-index card (§1.8) shows the locked-card *teaser*; no mockup shows what a visitor sees on click-through.
- **"Generating" / in-flight state for automated AARs.** The Dev Stories "execution → published" flow diagram (§1.5) implies a pipeline with a pending stage; no mockup shows an in-progress/generating card state distinct from the finished `Automated + Reviewed` pill.
