# Visual System & Assets — S2S v2 Redesign

Source of truth for this analysis: `signal-to-system-visual-handoff-v2/` (mockups, transparent asset sheets, hero backgrounds, reference boards) compared against `signal-to-system-build-handoff-v2/design/` (the *approved* HTML prototype, its design-token JSON, and `approved-design-board.jpg`). Per project instruction, the visual-handoff mockups are the default source of truth for *look and feel*; the build-handoff prototype and its token files are the source of truth for *what is actually implementable and named* (the Observatory/Folio/Instrument system, the `--bg-*`/`--text-*` mapping contract). All ten site mockups are 1448×1086px; all four transparent asset sheets are 1448×1086px; both hero backgrounds are 1672×941px. Pixel regions below are estimates against those canvases, quoted as `x,y,w,h` from the top-left.

**One critical, load-bearing finding up front:** the visual-handoff mockups and the build-handoff prototype are not two views of the same design — they are two different color systems wearing the same three names. The mockups render "Observatory" as a saturated cosmic-purple night scene (glowing violet/lavender accents, near-black `#0a0d10`-ish canvas, neon icon glows). The build-handoff's `observatory.tokens.json` defines Observatory as a *much* quieter charcoal (`canvas #111517`, `accent #B8A5F2` — a soft, desaturated lavender, not neon). Same story for Folio (mockups imply cream notebook paper with sepia ink; tokens confirm cream `#F6F1E7`/`#FFFAF1` with a muted rust `#974B32` accent — close alignment) and Instrument (mockups show a light "clinical" panel; tokens confirm near-white `#F0F4F7`/`#FFFFFF` with a saturated blue `#244FB0` — also close). **Observatory is the one language where the mockups' saturation should be turned down toward the token file, not the reverse** — see §2.

## 2. The emerging design system *(re-anchored 2026-09-22 — palette and language scope corrected)*

⚠️ **Visual authority correction.** The palette below was originally sourced from the build-handoff's `design/initial-language-skill/*.tokens.json` prototype files, treating the mockups' saturation as something to be "corrected toward" that prototype. That inverted the authority rule: the **visual-handoff mockups are the design authority**; the build-handoff prototype and its token JSONs are behavior/contract reference only, never a palette source. The values below are pixel-sampled directly from the site mockups and the logo board (via `PIL.Image.getpixel`/`getcolors` against the committed files in `docs/design/s2s-v2-visual/`), not read from any prototype token file.

- **Canvas** ≈`#0d1015` (near-black, cool). **Card/panel surface** ≈`#0f1317`–`#141820` (one step up from canvas). **Chip/pill surface** (third elevation, tags/badges) ≈`#25282d`–`#26282e`. **Rule/border** ≈`#363a3f`.
- **Ink** (H1/heading text) ≈ near-white, `#f5f3f7`–`#ffffff`. **Muted** (body copy, deks) ≈`#b7bac0`. **Muted-2** (eyebrow small-caps, meta labels) ≈`#6a6d71`.
- **Accent** (CTA buttons, bloom-affected highlights) ≈`#d2b8fc` at its brightest sampled point, consistent with a truer base accent in the **`#7C6FE0`–`#9B87F5`** range once bloom/glow is discounted — this is the same range the site's existing `--accent:#6366f1` should converge toward (warmer/lighter than the current indigo). **Secondary** (status-active dot, "green" accents) ≈`#8fdca4`–`#98e8ad`, a light sage-green.
- **Logo-board gradient core** (the primary lockup's icon fill) samples ≈`#915de7` on a `#07052f` card background — consistent with the accent range above and confirms the wordmark and the UI accent are meant to be the same hue family.
- **Folio** (paper/ink for Notebooks) and **Instrument** (light technical, seen once in the Studio mockup's bottom switcher) are real named skins the mockups themselves show, but — see the language-scope correction below — Folio is realized in the Notebooks mockup as individual cream-toned `NotebookLeaf` cards sitting *inside* the still-dark Observatory shell, not a full-page reskin; no mockup renders a full-page light/Instrument route to sample directly, so Instrument's exact hex values remain provisional pending a dedicated design pass.
- **Type pairing.** A serif display face (the wordmark and every mockup H1 — high-contrast old-style serif, visible in "Signal to System," "A more rigorous relationship with reality.") paired with a clean grotesque sans for UI/body (nav, buttons, labels, stat numbers) and a monospace for meta/status microtext (version strings, timestamps, chip labels). Three distinct roles, not the site's current two-family trio collapsed to one accent. Family selection is still open — the mockups' serif reads like a Georgia/Playfair-adjacent transitional serif — worth an actual type audit against Google Fonts before locking.
- **Spacing/density.** Mockup density is high (stat tiles, multi-row card grids) but each card interior still respects generous internal padding — nothing touches edge-to-edge. A 4/8/12/16/24/32/48/64px space scale and 720px reading width / 280px rail width remain reasonable targets consistent with the mockups' proportions, carried forward from the build-handoff's token files as an implementation convenience (a contract detail, not a claim about mockup-sampled color).
- **Iconography.** Two distinct icon languages appear and should NOT be merged: (1) the flat, thin-stroke UI icon grid (`neon_research_icon_grid.png`) — reusable, geometric, works at 20–24px; (2) the illustrated "sticker" artifacts (`cosmic_research_ui_sticker_sheet.png`) — rendered, painterly, decorative-only, never inline at icon size. No parallax or particle animation is implied anywhere — keep motion functional (tab switches, hover-reveal captions, chart interactions only).
- **Dark/light story, corrected.** Every one of the ten site mockups' headers — including the Studio mockup itself — shows only a plain sun/moon dark/light toggle, never a three-way control. The Observatory/Folio/Instrument switcher appears exactly once, as a bottom-of-page "Design Languages" 3-up section in the Studio mockup (§1.7) — a **Studio-scoped design-system documentation/showcase**, not a global site-wide theme switcher. Treat the three languages as real named skins worth keeping (Folio for Notebook-leaf cards, a possible Instrument pass for Studio/methods pages), but the **header control across the site stays the single sun/moon dark/light toggle every mockup actually shows** — do not replace it with a 3-way switcher, and do not read the Studio "Design Languages" tab as evidence that visitors toggle languages site-wide.

## 3. Brand — logo, wordmark, favicon *(re-anchored 2026-09-22 — primary-mark recommendation corrected)*

⚠️ **Correction.** This section previously recommended the build-handoff prototype's header "orbit/trail" mark (a ring crossed by an overshooting diagonal line, seen in `approved-design-board.jpg`) as the primary logo, on the reasoning that it was the only candidate validated at real UI scale. That reasoning treated the prototype header as visual authority; it is not — the prototype is behavior/contract reference only. **Nick's decision (2026-09-22): the visual pack's logo exploration board sets the marks**, all three below sampled and named directly off `docs/design/s2s-v2-visual/02-visual-assets-transparent/signal_to_system_logo_exploration_board.png`.

**Primary mark — "01 Primary Lockup" (waveform-diamond).** Top-left, largest treatment on the board: a diamond-framed waveform/pulse icon paired with the `Signal to System` serif wordmark. This is the mark that ships everywhere a full lockup is needed (header, footer, share cards, merch). Its icon-fill gradient core samples ≈`#915de7` on a `#07052f` panel — squarely in the `#7C6FE0`–`#9B87F5` accent range confirmed in §2, so the mark and the UI accent read as one identity with no separate palette to maintain.

**Favicon — "Favicon ideas" strip, icon 01 (waveform bars).** The favicon-ideas strip on the same board tries several marks at 120px; icon 01, a compact waveform-bars glyph, is the pick — it is the simplest silhouette in the strip and the one that survives flattening to 16px without losing its read. This is a distinct choice from the primary lockup's diamond-framed waveform: the favicon is the bars alone, no diamond frame, no wordmark.

**Secondary mark — "05 Monogram" (S/S, slash + sparkle).** An interlocked S/S monogram with a diagonal slash and a small sparkle accent. Use for square-format contexts where the full lockup doesn't fit: app icon, social avatar, a compact footer mark.

**Not promoted (alternates, board only, no UI use).** "02 Observatory Lockup" (dome-on-mountain icon), "03 Constellation Lockup" (node/line network icon), "04 Compass Lockup" (star compass icon) — all three are unbuilt exploration concepts on the same board; none is the primary, favicon, or secondary pick. They may be revisited as decorative/merch variants but should not appear as functional UI marks.

**Geometry note for the author.** Unlike the prototype's hand-authorable two-stroke orbit/trail mark, the waveform-diamond primary lockup and the favicon-01 waveform-bars glyph are the actual source-of-truth shapes to trace/vectorize directly from the logo board PNG (transparent background, so the shapes lift cleanly) rather than to re-derive from a written stroke spec — there is no equivalent "circle + chord" construction to hand-author; the mark is a diamond frame around a multi-bar waveform glyph, and getting its proportions right means tracing the board image, not reconstructing it from primitives.

**Wordmark lockup.** Horizontal: mark (~28–32px tall) + `Signal to System` in the serif display face, with `BY NICK MIETHE` in tracked-caps monospace beneath, matching the proportions shown on the logo board and the site mockups' header lockups. Stacked variant (mark above wordmark, tighter kerning) for square contexts.

**Favicon set.**
- `favicon.svg` — the favicon-01 waveform-bars glyph, colored via `var(--accent)` with a `@media (prefers-color-scheme: dark)` rule swapping between a light-canvas pair and the Observatory dark-canvas pair. Chrome/Firefox/Edge re-render this live on OS theme change.
- PNG fallback, rendered from the same SVG (never upscaled from a small rasterization): **16×16**, **32×32** (tab/bookmark), **180×180** (apple-touch-icon, flattened onto a solid dark canvas — no transparency support there), **192×192**, **512×512** (PWA manifest), plus one **maskable 512×512** with the mark inset to the standard ~80% safe-zone circle and a solid (not transparent) background fill for Android adaptive icons.

**OG-image template.** 1200×630, Observatory-dark canvas regardless of the source page's active theme (one consistent dark background reads correctly across both light- and dark-mode host UIs — never ship a light-Folio OG card). Layout: mark + wordmark lockup top-left at ~64px; a tracked-caps page-type kicker reusing the format-pill vocabulary from §4 (`ESSAY` / `LAB` / `DEV STORY` / `PROJECT`); the page H1 set large in the serif display face, ≤3 lines, left-aligned mid-canvas; an optional one-line dek below at reduced opacity; a thin rule + `nickmiethe.com` bottom-left; for Lab pages only, a status pill (`Published`/`Active`/`In Progress`, same pill component as §4) bottom-right. No painterly hero art on the card itself — the illustrated hero backgrounds (§4) stay on-site; OG generation needs to be fast, legible at thumbnail size, and theme-independent.

## 6. Gaps

No mockup exists for any of the following — each needs its own design pass before build, not an inferred extension of a desktop mockup:

- **Mobile layouts, full stop.** All ten mockups (and both hero backgrounds) are fixed 1448×1086 desktop canvases; nothing shows how the header nav collapses, how the multi-column card grids stack, how the right rails relocate, or how the Studio tab bar / Dev Stories tab-row behave under ~768px.
- **Article/essay reading page.** No mockup renders a single long-form post in any language — the closest analog is the prototype's plain-sans fixture (§1.1), which is explicitly a placeholder, not a designed reading page. This is the single highest-traffic template with zero visual direction.
- **404 / not-found.** `src/pages/404.astro` exists in code; no mockup covers it.
- **Empty, loading, and error states.** No mockup shows an empty search result, an empty filtered card grid ("no Labs match these filters"), a failed data-fetch state, or a "report unavailable" state for a withdrawn/retracted investigation — notable given how much of the Labs/Notebooks IA is filter-driven.
- **Withdrawn / retracted / under-review states.** The taxonomy implies a lab or claim can move backward (Peer Reviewed → under correction), per the `CorrectionNotice` component named in the Studio library (§1.7) — but no mockup shows what that state looks like on a live investigation page.
- **Search results page.** `search.json.ts` exists as a data endpoint; no mockup shows the results UI the "Search" nav icon (§4) presumably opens into.
- **Series / reading-path detail page.** `series/[...slug].astro` and the Writing hub's "Reading paths" rail both imply a page that walks a multi-post sequence; no mockup shows it.
- **Tags / topics index and detail.** `tags/[tag].astro`, `tags/index.astro`, `topics/[topic].astro` exist as routes; no mockup covers the tag-cloud index or a single tag's filtered results.
- **Newsletter subscribe confirmation / error.** The Writing-hub newsletter strip (§1.4) shows the input + button only, no success/already-subscribed/invalid-email states.
- **Full detail page behind a `Private Summary` project.** The Projects-index card (§1.8) shows the locked-card *teaser*; no mockup shows what a visitor sees on click-through.
- **"Generating" / in-flight state for automated AARs.** The Dev Stories "execution → published" flow diagram (§1.5) implies a pipeline with a pending stage; no mockup shows an in-progress/generating card state distinct from the finished `Automated + Reviewed` pill.
