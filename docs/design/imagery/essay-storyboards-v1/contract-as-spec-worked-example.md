## Boards

### worked-contract-record — optional net-new
- **Class:** figure. **Placement:** after opening contract block; anchor: `Feature Contract: fc-example-041`. **Purpose:** let the reader scan a record's obligatory fields as one object.
- **EXACT ON-IMAGE TEXT:** `fc-example-041` · `Status: accepted` · `Intent` · `Acceptance criteria` · `Evidence obligations` · `Decision authority`.
- **Composition / positioning:** paper document plate; record ID and status at top; four vertically stacked labelled field blocks; rule-separated evidence strip at bottom.
- **Layout:** `[fc-example-041] [Status: accepted]` then `Intent` / `Acceptance criteria` / `Evidence obligations` / `Decision authority`.
- **Scheme / variant / master:** paper-light / single / 1800×1350 (4:3).
- **Alt:** A structured feature-contract record shows its required fields.
- **Caption:** A contract is inspectable when its obligations are visible together.
- **Generator prompt:** Registry Wave document-as-evidence plate, disciplined whitespace, monospaced data cues, semantic role-slot accents.
- **Negative prompt:** invented contract prose, handwriting, legal-document clichés, UI chrome.
- **Acceptance checks:** only supplied labels; image is secondary to surrounding source text; readable at article width.

### worked-claim-binding — optional net-new
- **Class:** figure. **Placement:** after “Claims bound to evidence”; anchor: “Claims are bound to evidence.” **Purpose:** show that evidence attaches to claims and carries verification state.
- **EXACT ON-IMAGE TEXT:** `Claim` · `criterion 1` · `criterion 3` · `ev-01 pending` · `ev-02 verified` · `ev-03 verified` · `ev-04 verified`.
- **Composition / positioning:** claim card upper centre; four evidence records in lower grid; support lines run upward; state marker at each row end.
- **Layout:** `ev-01 pending ┐` / `ev-02 verified ├→ [Claim]` / `ev-03 verified ┤` / `ev-04 verified ┘`.
- **Scheme / variant / master:** paper-light / single / 2000×1125 (16:9).
- **Alt:** A claim is connected to four evidence records with pending and verified states.
- **Caption:** Evidence should attach to the claim, not merely surround it.
- **Generator prompt:** Registry Wave evidence-provenance diagram, sparse rows, clear status semantics, exact labels.
- **Negative prompt:** fabricated evidence IDs, checkmark overload, dashboards.
- **Acceptance checks:** labels exact; pending/verified differ beyond colour; no factual assertion beyond illustrative record.
