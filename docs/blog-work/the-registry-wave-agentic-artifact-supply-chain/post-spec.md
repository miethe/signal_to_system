## Core Thesis
Skills registries validate the first layer of the agentic artifact thesis, but enterprises will need a broader supply-chain control plane for skills, prompts, MCP servers, context packs, policies, evals, runtime bindings, evidence, and outcomes.

## Why Now
GitHub, JFrog, Red Hat, the official MCP Registry, and security/research communities are converging on package, registry, and governance semantics for agentic capabilities.

## Primary Insight
The market is validating that agentic capabilities are package-like. The durable enterprise problem is larger than discovery and install: it is lifecycle governance across artifact classes and runtimes.

## Supporting Arguments
- Agent behavior is shaped by reusable files, context, tools, and policy, not only model weights.
- Skills were the first obvious unit because they package behavior cleanly.
- Registries answer location, version, install, update, and publish questions.
- Enterprises must also answer approval, trust, policy, compatibility, revocation, provenance, and outcome questions.
- The artifact taxonomy extends beyond skills into instruction, tool, context, governance, execution, and evidence artifacts.

## Counterpoints / Risks
- Do not claim SkillMeat invented skills registries.
- Do not frame vendors as copying or competing with SkillMeat.
- Do not imply GitHub `gh skill` is a vetted marketplace.
- Do not imply the official MCP Registry hosts or scans server code.
- Keep SkillMeat implementation details abstract to avoid patent-sensitive disclosure.
