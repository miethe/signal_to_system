# Claims Safe To Publish

- Agentic capabilities are becoming reusable, versioned, distributable artifacts.
- Skills were the first obvious unit because they make agent behavior packageable.
- GitHub `gh skill` validates repository-native discovery, installation, publishing, update, and version pinning workflows for skills.
- JFrog validates the enterprise governance/security angle by treating skills as Artifactory/AI Catalog-managed assets.
- Red Hat validates the enterprise/operator angle by curating skills, agents, and MCP servers and by connecting MCP catalog discovery to OpenShift deployment/runtime patterns.
- The official MCP Registry validates metadata, discovery, namespace, and sub-registry semantics for MCP servers.
- Security and academic work supports the claim that skill metadata and skill packages are operational control surfaces with supply-chain risk.
- A registry answers location, install, version, update, and publish questions.
- An enterprise control plane must also answer trust, policy, compatibility, approval, revocation, provenance, evidence, and outcome questions.
- Agentic artifacts extend beyond skills into prompts, commands, hooks, MCP servers, context packs, policies, evals, workflows, agent definitions, traces, outputs, and provenance records.
- Enterprises are unlikely to accept separate governance models for every artifact class once agentic work moves from experimentation to delivery.
- Context should be treated as infrastructure because agent behavior depends heavily on current, governed, domain-specific context.
- Outcome evidence is a better executive metric than token counts, session counts, or number of agents.
